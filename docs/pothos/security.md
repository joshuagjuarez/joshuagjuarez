# Security reporting

Report suspected vulnerabilities privately to
[joshua@joshops.ai](mailto:joshua@joshops.ai) with the subject
**PothOS security report**.

Include the affected public source/version, expected behavior, observed behavior
and a minimal reproduction using synthetic data where possible. Describe what
boundary may fail without attaching another person's private records.

Do not send passwords, tokens, recovery codes, full memory exports, voice
recordings or unrelated personal information. Do not publish active credentials
or sensitive exploit details in public issues. If a secret is exposed, revoke it
through its actual provider; removing it from a new commit does not revoke it
or remove older copies.

A source license does not authorize access to another person's account, data
or hosted service. Avoid disruption and access to other users' information while
investigating a suspected problem.

## Current support scope

The published material is documentation and design source. A supported-runtime
version table will accompany the actual public runtime release. The existing
hosted beta has its own account and service boundaries.

Reports will be reviewed as capacity permits. There is no promised response
deadline, bounty or production support SLA. Coordinate disclosure through the
private route before publishing details that would expose users.

See [cognitive privacy](cognitive-privacy.md) for the release requirements.
